1. Introduction and Problem Statement

The Automated Voltage Regulator (AVR) system addresses the need to maintain a stable output voltage from a variable autotransformer (Variac) despite fluctuations in the generator's input voltage. In manual operation, a technician must continuously monitor the output and physically adjust the Variac's rotary knob to compensate for input drift — a tedious and error-prone process.

The relationship between input and output voltage in a Variac is governed by the transformer ratio equation:

Vout = Vin × (Dial Position / 220)
(Equation 1)

Where Dial Position ranges from 0 to 250, and 220 is the rated maximum input voltage. This equation shows that for a constant output voltage, any change in Vin requires a proportional inverse change in dial position. The firmware automates this compensation using a closed-loop control system with continuous servo adjustment.

The target application requires maintaining a stable 25V output (±1V tolerance) during varying input conditions, specifically for testing voltage stability during Vin movements in the 24–25V output range.

4. Sensor Integration and Signal Processing

4.1 Voltage Sensing (ZMPT101B)

Two ZMPT101B voltage transformer modules are used to measure Vin (pin A3) and Vout (pin A0). The custom ZMPT101B_DRIVER library implements non-blocking RMS voltage calculation using continuous sampling:

ParameterValueRationale
Sampling rate4 kHz (every 250 µs)≈66 samples per 60 Hz cycle — sufficient for accurate RMS
DC offset filterLow-pass, α = 0.001Time constant ~250 ms — tracks sensor drift without reacting to AC signal
RMS windowOne AC period (16.6 ms at 60 Hz)Produces one RMS value per cycle, eliminates partial-cycle errors
Sensitivity500.0Scaling factor for voltage conversion
ADC Cross-talk Mitigation: The Arduino's ADC multiplexer shares a single sample-and-hold capacitor across all analog pins. When switching between pins rapidly, residual charge from the previous reading can contaminate the next. The firmware performs a dummy analogRead() on each pin before the sensor's internal read to flush the capacitor.

4.2 Voltage Smoothing (Moving Average Filter)

The Vout reading is passed through a 10-sample circular buffer moving average filter before being used by the regulation algorithm. This eliminates high-frequency sensor noise that could trigger unnecessary servo corrections.

Vout(averaged) = (1/N) × Σ Vout(sample)[i],   N = 10
(Equation 2)

The raw (unfiltered) Vout is retained separately for diagnostic purposes and displayed in the serial debug output as Vout, while the averaged value is displayed as V_avg and used for all regulation decisions.

4.3 Current Sensing (ACS712-20A)

Output current is measured using an ACS712-20A Hall-effect sensor via the ACS712-driver library. The reading uses a time-sliced blocking approach:

ParameterValueRationale
Read methodreadCurrentAC(60)True RMS over one 60 Hz cycle
Block duration~20 msOne full AC cycle for accurate RMS
Read intervalEvery 500 msLimits blocking to 4% of total execution time
Sensitivity0.100 V/APer ACS712-20A datasheet specification

On boot, calibrate() is called with no load to auto-zero the sensor baseline, compensating for manufacturing variations in the Hall-effect element.

4.4 Display Units

Current values automatically switch display units based on magnitude: values ≥ 1.0 A are shown in Amperes (e.g., 1.50A), while values below 1.0 A are converted to milliamperes (e.g., 300mA) for improved readability. This applies to both the LCD and serial output.

5. Closed-Loop Regulation Algorithm

The regulation algorithm implements a Vout closed-loop control system where the output voltage sensor provides direct feedback. Unlike open-loop approaches that calculate dial position from Vin, this design directly measures and corrects Vout, making it inherently robust against mechanical backlash, sensor calibration drift, and non-linear transformer behavior.

5.1 Algorithm Pseudocode

FUNCTION regulateLoop():
    IF Vin < 5V:
        STOP servo   // Generator is off
        RETURN

    error = targetVoltage - smoothedVout
    absError = |error|

    SWITCH servoState:

        CASE SERVO_IDLE:
            IF absError > tolerance:
                IF confirmationTimer not started:
                    START confirmationTimer
                IF confirmationTimer >= 3 seconds:
                    TRANSITION → SERVO_SETTLING
            ELSE:
                RESET confirmationTimer   // Back within tolerance

        CASE SERVO_SETTLING:
            STOP servo
            WAIT 150ms
            RE-READ error from sensors
            IF absError <= tolerance:
                TRANSITION → SERVO_IDLE
            ELSE:
                speed = proportionalSpeed(absError)
                direction = (error > 0) ? CW : CCW
                START servo at (1500 ± speed) µs
                TRANSITION → SERVO_PULSING

        CASE SERVO_PULSING:
            AFTER 80ms:
                STOP servo
                TRANSITION → SERVO_SETTLING

5.2 Proportional Speed Control

The servo speed is scaled proportionally to the magnitude of the error, implementing a simplified proportional controller. This prevents overshoot when the error is small while allowing rapid correction for large deviations:

Error MagnitudeSpeed Offset (µs)Servo Command (µs)Behavior
> 30V±2001700 (CW) / 1300 (CCW)Fast — large correction needed
10–30V±1001600 (CW) / 1400 (CCW)Medium — moderate approach
< 10V±501550 (CW) / 1450 (CCW)Slow — fine positioning near target

6. Stability Mechanisms

Three mechanisms work together to prevent servo hunting (oscillation around the target) and ensure stable regulation:

6.1 Moving Average Filter (Signal Level)

Eliminates high-frequency noise from Vout readings. Without this filter, individual sensor readings may fluctuate by ±5V due to electromagnetic interference and ADC quantization noise. The 10-sample average reduces this to ±1V, which is within the tolerance band.

6.2 Confirmation Window (Decision Level)

The servo does not react immediately when Vout leaves the tolerance band. Instead, a 3-second confirmation window requires the error to persist continuously before the servo begins correcting. This prevents the servo from reacting to:

  • Momentary Vin fluctuations that self-correct
  • Load transients (sudden current draw changes)
  • Sensor noise that exceeds the filter's capability

If Vout returns to within tolerance at any point during the 3-second window, the timer is reset and the servo remains idle.

6.3 Pulse-and-Wait (Actuation Level)

Rather than continuously spinning the servo, corrections are applied in discrete micro-steps:

  1. Pulse — Spin for exactly 80 ms
  2. Stop — Immediately stop the servo
  3. Wait — Allow 150 ms for the Variac's mechanical components to settle
  4. Measure — Re-read Vout to determine if further correction is needed

This prevents overshoot by allowing the system to observe the effect of each small correction before deciding whether to continue. Each pulse moves the Variac knob by approximately 1–3V depending on speed level.

Combined Effect: These three layers create a progressively filtered control pipeline: the moving average smooths sensor noise, the confirmation window ignores transient disturbances, and the pulse-and-wait strategy prevents mechanical overshoot. Together, they enable the system to maintain Vout within ±1V of the target without oscillation.

7. Alarm Detection and Self-Recovery

7.1 Stall Detection

The system monitors whether Vout is actually changing in response to servo corrections. If the servo has been actively pulsing but Vout has not changed by more than 1V for 3 seconds (STALL_TIMEOUT), it concludes that the Variac has reached a physical limit:

Pulse DirectionPhysical MeaningAlarm State
Clockwise (+1)Trying to increase Vout but Variac dial is at maximum (250)REG_UNDER_VOLTAGE
Counter-clockwise (-1)Trying to decrease Vout but Variac dial is at minimum (0)REG_OVER_VOLTAGE

7.2 Automatic Recovery

Alarm states are self-recovering. The system continuously monitors even while in alarm, and automatically transitions back to REG_ACTIVE when conditions improve:

AlarmRecovery ConditionMathematical Basis
REG_UNDER_VOLTAGEVin has increased sufficientlyVin × (250/220) ≥ targetVoltage
REG_OVER_VOLTAGEVout has dropped back into rangeVout ≤ targetVoltage + tolerance

No user intervention is required. This is critical for unattended operation where the generator's output may temporarily drop below usable levels and then recover.

8. Servo Motor Control Strategy

8.1 Modified MG996R for Continuous Rotation

The standard MG996R is a 180° position servo. For this project, it has been modified for continuous 360° rotation by removing the internal position feedback mechanism. In this mode, the servo responds to PWM signals as follows:

PWM Signal (µs)BehaviorApplication
1500Stop (zero speed)Hold position
> 1500Clockwise rotationIncrease Vout
< 1500Counter-clockwise rotationDecrease Vout

8.2 Servo Detachment (Drift Prevention)

When the servo is idle, the PWM signal is completely detached using variacServo.detach(). This is necessary because the modified MG996R exhibits slight drift when receiving a continuous 1500 µs signal due to internal resistor imbalance. Detaching eliminates the PWM output entirely, ensuring zero movement when idle.

8.3 Homing Sequence

On boot, the servo performs a homing routine by spinning counter-clockwise at a slow speed (1300 µs) while monitoring the internal potentiometer feedback (pin A2). When the POT reading drops to ≤ POT_HOME_VALUE (5), the servo has reached the physical 0V stop. This establishes a known starting position before regulation begins.

A 15-second timeout prevents indefinite spinning in case of mechanical failure or sensor malfunction.

9.3 LCD Update Strategy

Static menu screens (HOME, CONFIGURE, VIEW_STATUS) are drawn once when entered and do not refresh. Live data screens (VIEW_INPUT, VIEW_OUTPUT) refresh every 500 ms using a non-blocking timer to prevent LCD flicker while keeping readings current.

10. Persistent Storage (EEPROM)

Two user configuration values are stored in the ATmega328P's built-in EEPROM, allowing them to survive power cycles:

AddressDataValid RangeDefaultBehavior on Boot
Byte 0Tolerance (±V)1–992VLoaded and applied immediately
Byte 1Target voltage0–250None (0xFF)If valid → auto-starts regulation

A fresh (unprogrammed) EEPROM byte reads as 0xFF (255). The firmware uses this as a sentinel value to detect "no saved data" and applies defaults. Values are written using EEPROM.write() which only writes if the value has changed, extending EEPROM lifespan (rated for 100,000 write cycles per byte).

Auto-Regulation on Boot: If a valid target voltage is found in EEPROM, the system will automatically begin regulating to that target after homing — no user interaction required. This is essential for unattended operation after power interruptions.

The baud rate of 115,200 was chosen specifically to ensure that the serial output (~120 characters per line) transmits within ~1 ms, preventing the UART buffer from blocking the main loop. At 9,600 baud, the same output would require ~12.5 ms, which would interfere with the 500 ms sensor timing.

16. Key Design Decisions and Rationale

DecisionAlternatives ConsideredRationale
Closed-loop (Vout feedback) Open-loop (calculate dial from Vin) Self-correcting for mechanical backlash, transformer non-linearity, and calibration drift. Only requires accurate Vout sensor.
Pulse-and-wait servo control Continuous spinning, PID controller Simpler to tune than PID. Mechanical Variac has significant inertia — continuous control would overshoot. Discrete steps allow observation between actions.
3-second confirmation window Immediate response, hysteresis band Prevents hunting from transient Vin fluctuations. A 3-second sustained error is strong evidence of a genuine drift requiring correction.
Moving average filter (N=10) Exponential filter, median filter Simple to implement, predictable latency (~170 ms window at 60 Hz update rate), effective at removing ZMPT101B noise.
Non-blocking architecture Blocking delays, RTOS ATmega328P has no RTOS support. Non-blocking millis()-based timing ensures keypad, sensors, regulation, and UI all run concurrently without missing events.
Servo detach when idle Continuous 1500 µs signal Modified MG996R drifts at 1500 µs due to internal resistor imbalance. Detaching PWM eliminates drift completely.
EEPROM persistence Volatile memory only Enables auto-resume after power interruptions. Critical for unattended operation where the system must restore its target and tolerance without user input.
115,200 baud serial 9,600 baud (default) Debug output (~120 chars) at 9,600 baud takes 12.5 ms — enough to disrupt 500 ms sensor timing. At 115,200 baud, the same output takes <1 ms.
